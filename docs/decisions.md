# Decision Ledger

One line per decision that shapes the language or how it is built, newest
first. Each entry names who decided and where the detail lives. Specs and
tickets hold the full reasoning; this page is for scanning and overruling.

`User` means Byron decided directly. `Coordinator` means the implementation
coordinator decided under the standing instruction to settle minor details
from the philosophy and earlier decisions; any of these can be overruled.

Standard output and error stay blocking, since their file description is shared with the parent; the runtime writes at most `PIPE_BUF` bytes after poll says writable (`send(MSG_DONTWAIT)` for a socket). Lines go whole onto a per-stream queue (at most 1 MiB) that any waiting writer drains, so lines from different tasks never interleave and a line once queued is written whole even if its writer is cancelled. Regular files, programs without the scheduler, and every `--clock=virtual` run keep the direct blocking write, so virtual-clock task order does not depend on how fast a pipe is read. A wait that answers ERROR fails the line, as a read of `"-"` does, rather than writing blocking. | Implementer (CHI-266 lane), Fable advisor | host-capabilities-and-execution-properties.md, "Waiting for descriptors"; `runtime.c` `console_write_line` |
