# Decision Ledger

One line per decision that shapes the language or how it is built, newest
first. Each entry names who decided and where the detail lives. Specs and
tickets hold the full reasoning; this page is for scanning and overruling.

`User` means Byron decided directly. `Coordinator` means the implementation
coordinator decided under the standing instruction to settle minor details
from the philosophy and earlier decisions; any of these can be overruled.

| 2026-11-16 | `std/net` is a `Network` interface (`connect`, `listen`) under the fixed need `network`, which also covers name lookup and listening. A connection is a pair of byte streams plus its addresses and a `close`; `Stream.close` on its writer is a half-close. Connections and listeners are reached through `Net.*` functions, since published structs keep their fields private, and `Net.pair`, `Net.connection`, `Net.listener` and `Net.address` build fakes. Name lookup runs on a detached thread (at most 8 at once) that the calling task waits on through the reactor. A test opens real sockets only through the test-only `Net.host_for_tests()`. A socket wait holds virtual time, so tests that mix sockets and timers use `--clock=real`. | Claude (Fable advisor) | One need keeps every service's signature short, and the thread keeps the C library's resolver settings without blocking the scheduler. `Net.host_for_tests()` is the recommendation on Byron's open card; the alternatives were `Test.real_network()` or no real network in tests. `network-modules.md`; CHI-255. |
| 2026-11-16 | A descriptor wait may name the host resource its descriptor belongs to, and `CHIMI_REQUEST_IO_WITHDRAW` wakes every wait on that resource; closing a binding handle issues it before the handle's release, so a waiter never stays parked on a descriptor number the close frees for reuse.
