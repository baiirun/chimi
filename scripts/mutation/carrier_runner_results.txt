so the spawned carrier usually read the gate only after it was closed. The

The verifier's own fifteen mutants left six alive. Deleting the begin_run
before the carriers start was real: a carrier with no work could read the
last run's end and leave before carrier 0 cleared it, which only a race
window showed. The run now asserts the end is cleared (the last mutant
above). The others are equivalent or unobservable: removing either
abort_on_panic (no test panics), a stale run end set on a failed start (the
next begin_run clears it), clobbering the current carrier (Locked resets it
on every access), and the ABI path skipping the lock (one carrier behaves
the same). The guard that sends carriers away if the spawning loop unwinds
has no test, since nothing there panics in practice.
